# 酒店报价缺失会话复盘

> 定位：诊断导出会话中酒店报价缺失的原因，记录修复的证据边界。
> 状态：frozen（2026-10-07）。
> 上游：[架构](../architecture.zh-CN.md)、[数据源](../data-sources.zh-CN.md)。
> 下游：酒店检索回归与原生 HotelByte 配置流程。
> 信源：私有会话导出、只读供应商调用与官方酒店页面；原始轨迹和凭证不入库。

## 1. 结论

这段会话没有证明长春或哈尔滨无房。它把失败的观测当成空库存，并在机票失败后阻断了独立的酒店供应商。

| 故障 | 证据 | 修复 |
|---|---|---|
| hbcli 失败被报告为实时零库存 | 会话酒店工具报告零家酒店。只读复查得到业务码 `300010002`，进程退出码仍为零，含义是未配置可用供应商；封装此前把缺失列表计为零。 | 拒绝业务错误和无效酒店列表；保留错误证据，提供其他酒店通道。 |
| FlyAI 酒店被机票故障阻断 | 会话在机票失败后打开共享的 `FLYAI_SEARCH` 断路器，酒店查询随后直接被拒绝。当前独立酒店查询返回六条长春带价结果。 | 按业务类型隔离断路器；机票保护继续生效，酒店独立执行。 |
| 可选评级字段导致有效 FlyAI 报价被拒绝 | 当前哈尔滨回包含九家有名称、有价格的酒店；其中一家民宿的 `star: " "` 导致解析器拒绝全部九条。 | 将空白星级视为未评级，保留全部有效报价；字段类型及核心字段仍严格校验。 |
| 携程超时被归因于酒店嗅探 | 8000ms 超时属于 Cookie 名称登录态预检；酒店嗅探有独立超时。 | 标明作业类型及未领取、已领取阶段；心跳不代表作业完成。 |
| 携程失败观测可能被登记为酒店负面事实 | 空正文、坏 JSON、未知回包和嗅探超时此前都会落入成功的无结果分支。 | 失败时拒绝产出库存结论；只有明确的空酒店数组，且没有错误外壳或未解析条目，才产生无结果。 |
| 哈尔滨酒店入口无法解析 | 城市码表缺少哈尔滨；官方酒店列表页确认城市编号为 `5`。 | 加入已验证编号，并回归锁定日期与入住人数。 |

原生配置页现在在 FlyAI 旁提供 HotelByte。App Key 和 App Secret 使用保密输入框，保存到官方凭证文件的 `openapi:uat` 条目。验证在临时凭证目录中进行，保留其他认证方式和环境；供应商配置错误有独立可见状态，不会被当成库存查询通过。

## 3. 验证与剩余边界

回归套件覆盖真实注册的酒店工具、假 CLI 的实际进程调用、生产解译器、会话采集器与真实 HTTP 桥队列，区分业务错误、无效列表、明确空列表、挑战和领取阶段。原生配置测试覆盖验证、取消、并发修改、保密错误、原凭证保留和供应商状态。

隔离测试不代表真实扩展检索成功。已安装扩展当前有心跳，但历史登录态预检超时的具体传输故障尚未确认；用户没有看到扩展错误。修复让后续失败可诊断，不能据此宣称扩展回包闭环已恢复。

当前 hbcli 账号仍需 HotelByte 开通供应商；修改本机凭证不能凭空产生库存。GUI 提供官方沙箱申请指引，并解释此状态。正在运行的 Web 进程需要加载新代码才能显示新界面；源码变更不代表 npm 已发布。

没有变更预订、支付、供应商配置、共享动机档案或共享愿望池。
