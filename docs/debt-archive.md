**D-17 Z3 WASM race (README Known limitation)**

**Re-fixed and paid off 2026-09-08 (issue #227)**: the 08-29 singleton+mutex fixed three-module multi-instance and explicit concurrency, but Node24 full-stack run-all §30 still intermittently showed `Aborted(Runtime error: The application has corrupted its heap memory area (address zero)!)`. New root-cause evidence: ① cold-start concurrent `getZ3()` caches the Promise after await and can create multiple high-level Context objects; ② `z3-solver@5.2.0`'s high-level `FinalizationRegistry` cleanup directly calls native `dec_ref`/`*_dec_ref`, which at GC timing can bypass `withZ3` and race the actual native check. Fix anchors: `z3-shared.ts` caches the Promise first + `enable_concurrent_dec_ref` fail-closed + low-level cleanup local queue + actual async native barrier + fatal poison; engine/journey/unified explicitly release Solver/Optimize/Model to reduce GC pressure without freeing live objects early. Counter-evidence anchors: `z3-lifecycle-tests.ts`/`z3-lifecycle-fault-tests.ts`/`z3-race-repeat-tests.ts`; run-all §30/§30b/§30c.
