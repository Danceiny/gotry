# AaaS 安全设计：威胁模型（初稿）

> 定位：多用户 GoTry 服务的威胁模型——资产、参与者、信任边界、威胁，以及每项威胁的控制措施与证明阶段。
> 状态：proposal（[#674](https://github.com/Danceiny/gotry/issues/674) 的 A0，2026-10-26 起草）。[AaaS RFC](../rfc/aaas-rfc.zh-CN.md) 被接受后转为 living。
> 上游：[AaaS RFC](../rfc/aaas-rfc.zh-CN.md)；[architecture](../architecture.zh-CN.md) §1.3 不变量与 ADR-23；hotel-be 部署约束 C2、C6、C10、C13、C14、C15 与 C16。
> 下游：A2 对抗套件、A3 边界 ADR 与故障演练，以及 [安全策略](../ops/security.zh-CN.md) 的维护者。
> 证据边界：本稿是分析，不是证明。只有对应的证伪测试存在且通过，一项威胁才算已缓解。演练与夹具只证明工程行为。

## 速览

- 影响最大的威胁：跨租户访问（S-1 至 S-4）、跨组织桥路由落到另一组织的供应商登录态（S-5）、过期 owner 的写入（S-6），以及流量离开回环后的 bearer key（S-7、S-8）。
- 两条不变量承担了大部分防护：租户只在可信接缝处派生；每次持久写都按 epoch fencing。
- 现在按节点的形态主要靠回环边界（C2、C16）与 ADR-23 request binding 保护。AaaS 去掉了回环前提，所以 A2 与 A3 必须把它替换掉。
- 供应商登录态不进云。AaaS 不新增任何服务端会话存储。
- 拒绝服务主要是成本问题：LLM 预算、planner worker、桥长轮询，以及组织共用的供应商登录态。

## 1. 范围与资产

| 资产 | 存放位置 | 为何重要 |
|---|---|---|
| 租户账本 | 动机、心愿池、同行人、时间线、Booking Copilot 任务、工单 | 个人数据；同行人约束可能包含健康与饮食信息 |
| 租户工作文件 | planner 工作目录、handoff 工单、交付物、artifact | 敏感度与账本相同 |
| 组织桥车道 | `bridge.db` 与扩展长轮询 | 把 job 路由到员工浏览器里真实的供应商登录态上 |
| 服务凭证 | 每个服务面一把 BFF bearer key（C13）；LLM 供应商密钥 | 冒充与花费 |
| 预算 | LLM token、planner worker、供应商节律 | 成本，以及组织在供应商处的信誉 |
| 异地副本 | 复制出的租户文件与快照 | 已删除的数据可能残留在这里 |

## 2. 参与者与信任边界

| 参与者 | 信任 | 说明 |
|---|---|---|
| 终端用户（租户） | 由组织的 BFF 认证 | 可能对其他租户好奇或怀有敌意 |
| 组织 BFF | 被信任去认证用户并断言 principal | 采用按组织的凭证后，被攻破的 BFF 只能冒充本组织的用户 |
| 浏览器扩展 | 员工浏览器内不可信的传输通道 | 持有供应商登录态；以 hotel-be 签发的组织作用域 join ticket 认证（C16） |
| 副本运维者 | 被信任可访问主机 | 访问留审计；异地副本加密 |
| 内容来源 | 不可信 | 供应商页面、网页结果与模型输出都是数据，绝非指令 |
| 内网对端 | 不可信 | 该层离开回环后（A3）才相关 |

信任边界：浏览器到 BFF（权威在 hotel-be）；BFF 到 gotry 层（现为回环，A3 起为内网）；副本到租约存储与对象存储；同一副本内租户与租户之间。

## 3. 威胁

| 编号 | 威胁 | 现状 | 拟议控制 | 证明阶段与证伪测试 |
|---|---|---|---|---|
| S-1 | 请求携带或篡改 tenant id，以读取其他租户的状态 | 服务端路径共享租户 `local`；ADR-23 绑定 principal 与 scope 摘要 | 只在接缝派生（`HMAC(K_org, issuer ‖ subject)`）；没有 API 接受 tenant id | A2：请求体、header、工具参数与模型输出中伪造的租户字段一律被忽略或拒绝 |
| S-2 | 共享状态经共享账本、缓存、planner 会话或工作目录在租户间泄漏 | 每个节点一本 `local` 账本 | 每个租户一本账本、一个工作目录；planner 会话与缓存以租户为键 | A2：任务句柄、request key 与心愿名都相互碰撞的两个租户，各自只读到自己的行 |
| S-3 | id 被当作路径并逃出其目录 | id 按服务面校验 | tenant id 是固定格式的十六进制摘要；路径只由它构造 | A2：形如路径与超长的 id 在任何文件系统调用之前被拒 |
| S-4 | 租户 B 重放租户 A 的句柄（`taskHandle`、`requestKey`、artifact id） | 句柄绑定 principal 与 scope 摘要 | 句柄只在调用方自己的租户账本内解析 | A2：他人句柄返回 not-found，绝不返回其他租户的数据 |
| S-5 | 组织 A 的桥 job 在组织 B 的扩展上、用 B 的供应商登录态执行，或 B 的结果回到 A | 没有组织列；按站点、origin 与 client id 匹配 | 组织作用域的桥账本与 owner；匹配要求组织相同；组织作用域的 join ticket | A2：跨组织的领取与回包被拒，且不留任何行 |
| S-6 | 分区或停顿之后，过期 owner 继续写入 | 单节点，不适用 | 带 epoch 的租约；按 epoch 分区的持久副本；自我隔离 margin | A1：被暂停的 owner 在接管之后的写入，从不出现在恢复出的账本中 |
| S-7 | 流量离开回环后 bearer key 被嗅探或泄漏 | 只走回环（C2）；每个服务面一把 key（C13） | 按组织的凭证，配 mTLS 或短时签名断言；密钥轮换 | A3：边界 ADR 的测试拒绝未认证与跨组织的调用 |
| S-8 | 任何持有 BFF key 的人都能断言任意 principal | 只有本机 BFF 持有 key 时可以接受 | 按组织签名并绑定 request 摘要的断言；principal 摘要留审计 | A3：用 A 的密钥签发的组织 B 断言被拒 |
| S-9 | 供应商登录态进入云端 | 红线：cookie 值从不经过桥协议（扩展测试 §38） | AaaS 不新增服务端会话存储；任何 schema 都不携带 cookie 值 | A2：schema 扫描找不到 cookie 值字段 |
| S-10 | 单个租户耗尽 LLM 预算、planner worker、长轮询槽位或账本空间 | 请求体上限；每轮截止时间 | 按租户、按组织的配额；全局 worker 上限；typed 429 | A2：一个租户的洪峰下，另一个租户的延迟仍在预算内 |
| S-11 | 单个租户让组织共用的供应商登录态被限流或封禁 | 节律按节点、按站点 | 节律按组织、按站点，并按租户分配份额 | A2：一个租户的突发在到达站点之前即被限流 |
| S-12 | 已删除的数据残留在异地副本中 | 尚无异地副本 | 每租户数据密钥；forget 销毁密钥 | A1：forget 之后，恢复任何副本都读不出该租户的数据 |
| S-13 | 运维者读取租户文件 | 专用服务用户与 `umask 0077`（C6、C14） | 加密的异地副本；访问留审计 | A3：演练证明没有租户密钥就读不了副本 |
| S-14 | 被注入的内容触发跨租户读取或写动作 | 观测结果是数据；写路径封存 | 工具不带租户参数；WriteGate 不变 | A2：点名其他租户的注入指令不产生任何跨租户读取 |
| S-15 | 截获的 BFF 请求被重放 | request key 幂等 | request key 按租户作用域；断言会过期 | A2：重放返回原结果，不产生新效果 |
| S-16 | 版本混跑的集群启用了部分副本不具备的特性 | 特性交集规则（ADR-23） | 所有权只在兼容的副本之间移动 | A3：滚动发布演练中，直到全部副本都公告某可选特性之前，它保持关闭 |

## 4. 安全不变量

1. 租户在可信接缝处、由已认证的 principal 派生，别处一律不派生。
2. 每次持久写都携带其写者的 epoch；更低的 epoch 永远不会成为权威。
3. 租户的账本、文件、缓存与 planner 会话只能经该租户的句柄触达。
4. 桥 job 与结果从不跨越组织。
5. 服务端不存在任何供应商凭证值。
6. forget 把租户从每一份副本中移除，包括异地副本。
7. gotry 层永远不被浏览器触达（C16）。

## 5. 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 让浏览器或扩展直接调用 gotry 层 | 会把服务端密钥交给浏览器，并让 gotry 变成浏览器可达（C16） |
| 接受 BFF 载荷里的 tenant id | 任何载荷缺陷都会变成跨租户访问；租户改由接缝派生 |
| 依赖不带 fencing 的 Redis 或数据库锁 | 锁丢失或重复时会让两个写者都提交 |
| 在服务端保存供应商 cookie 以共享登录态 | 违反 2026-09-11 的决定，并把服务变成登录态农场 |
| forget 只删除、不销毁密钥 | 副本与快照仍会保留数据 |

## 6. 待解问题

- BFF 能签发哪种签名断言格式，以及由谁轮换其密钥（A3 边界 ADR）。
- hotelbyte 的对象存储是否支持客户自管密钥的服务端加密（RFC 事实项 F-3）。
- 异地副本保留多久之后，密码学粉碎成为唯一的删除路径（RFC Q5）。
