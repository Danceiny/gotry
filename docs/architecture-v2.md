## 1. 全景:我们到底在什么阶段

**一句话现状:GoTry 目前是「确定性规划管道」,还不是「Agent 系统」——引擎和数据是真的,对话、记忆、编排还没有进环。**

```
                     目标架构(总纲 3.2)                          现状(2026-08-22)
┌─────────────────────────────────────────────┐    ┌─────────────────────────────┐
│ L1 交互:App/Web 对话,动机访谈界面            │    │ ✗ 无(规划书是静态 markdown)  │
│ L2 编排:dsh 运行时 + gotry 插件(ReAct/Graph) │    │ △ 插件已写好并 smoke,运行时  │
│     PureAgent 对话 / WriteGate / gate 选择题  │    │   未跑(缺 DEEPSEEK_API_KEY) │
│ L3 领域:可行性引擎 / 统一行程模型 / TrueCost  │    │ ✓ 引擎可用,但分裂为两套面    │
│     记忆 / 透明卡片 / wish pool              │    │   (见§3 裂缝)               │
│ L4 能力:hotelbyte-cli / 航班数据 / 共享经验  │    │ △ 静态数据包(公开渠道调研)   │
│ L5 控制平面:loopx(目标/门/证据/配额)         │    │ ✓ 已运行,驱动 demo 迭代     │
└─────────────────────────────────────────────┘    └─────────────────────────────┘
```

**差距判断(排序即优先级)**:
1. **L2 未进环是最大缺口**:没有 LLM,「素材→约束的翻译」「结果的解释」「动机访谈」全部由人(我)代劳——demo 证明的是 L3/L4 的价值,还没证明 agent 形态本身。
2. **L3 有结构债**:engine(单候选选择)与 journey(多段链)两套求解面复制了算术层(§3)。
3. **L1 完全空白**:gate 选择题、透明卡片这些产品机制没有承载界面——它们目前活在文档里。
4. **L4 静态**:价格/班期是估算包;真实供应链(hotelbyte-cli、航班 API)未接。

## 2. 分层职责与架构不变量

| 层 | 职责 | 契约 | 不变量(任何演进不得破坏) |
|---|---|---|---|
| L1 | 呈现与采集 | 透明卡片 schema(D1 §6) | why/cost 必达用户;gate 只能是选择题 |
| L2 | 理解与编排 | dsh 工具 schema(gotry-tools) | 写操作必过 WriteGate;LLM 不做算术判定 |
| L3 | 判定与核算 | 统一行程模型(§3)+TrueCost | 算术与求解分层;算术纯函数可独立测试 |
| L4 | 数据与能力 | CLI/JSON 桥(hotelbyte-cli 式) | 证据链标注([实时API]/[共享经验]/[估算]);估算必须显式标记 |
| L5 | 治理 | loopx 状态(objective/gate/evidence/quota) | 验证后才花费;阻塞记录而非空转 |

## 3. 统一行程领域模型(修复当前最大的结构裂缝)

**裂缝**:`engine.py/ts`(N 个候选目的地,单 out/ret)与 `journey.py/ts`(M 段固定链)是两套并行求解面,门到门算术在两边各写了一份(model.evaluate_choice 与 journey.evaluate_leg)。洱海案例用前者,demo 行程用后者——**同一领域两个模型,是演进的最大隐患**。

**统一方向:行程 = 候选段(choices)的序列**。

```
JourneySpec:
  segments: [ Segment ]            # 顺序链
  Segment:
    role: fixed | almighty_choice  # fixed:日期班次已定(如 EK329 锚点)
                                   # almighty_choice:多候选(目的地×班次×接驳)
    options: [ Option ]            # 每个 Option = (目的地, services, transfers, stay, imagery)
    anchors: { arrive_by?, depart_after?, min_days? }
```

- 洱海案例 = 1 个 almighty_choice 段(3 目的地候选);demo 行程 = 5 段(f1 可 choice、f5 fixed)。
- 单候选引擎是统一模型在「单段」上的退化——**迁移以 journey 侧为基座**,engine 降级为兼容层,验证等价后退役。
- 算术层只此一份:`evaluate_segment`(现 evaluate_leg 泛化)+ 累计核算。

**迁移步骤(每步可独立验证,已挂 loopx)**:
1. Segment/Option 模型定义 + 从两种旧输入的适配解析;
2. journey 求解器吃 Segment 链(引擎行为不变,测试保绿);
3. 洱海金标准用例改跑统一模型,输出与旧 engine 对账;
4. engine.* 标记 deprecated,差分测试改为 统一模型(TS) vs 统一模型(Python oracle)。

## 4. 演进路线:五个阶段

每阶段有**进入条件(Entry)/退出条件(Exit)/该阶段不许做的事**。原则:不跳阶段,不提前优化下阶段的事。

### Stage 0:确定性管道(✅ 已完成)
- 产出:引擎双实现、五段真实数据包、规划书 demo、对账框架。
- Exit 已达成:引擎能对真实复杂行程给出「可行/不可行+归因+代价」。

### Stage 1:LLM 进环(agent 形态首次成立)← **当前位置**
- Entry:dsh 运行时跑通(需 DEEPSEEK_API_KEY)+ 统一模型完成§3 迁移。
- 做什么:动机访谈对话(PureAgent)→ LLM 抽取 JourneySpec → 统一引擎求解 → LLM 把结果讲成人话(含 gate 选择题渲染)。「一小时后不失望」异步模式在真实 loopx tick 上跑一次。
- Exit:用户一句自然语言进、得到对话级的规划+选择题出,**全程无人代劳翻译**。
- 不许做:真实供应链接入、UI 工程、B2B。

### Stage 2:实时数据(静态包退役为测试夹具)
- Entry:Stage 1 exit + 供应链选型(机票数据源决策;酒店走 hotelbyte-cli 桥)。
- 做什么:capability-hotelbe 插件(import/extend hotelbyte-cli)、航班数据源桥;证据链从「[估算]」逐步替换为「[实时API]+抓取时间」。
- Exit:同一 JourneySpec 实时数据求解与静态包结果差异可度量、可归因。
- 不许做:B2B、记忆系统。

### Stage 3:记忆与「下一次出发」
- Entry:Stage 2 exit。
- 做什么:动机画像/偏好/历史落盘(六层 memory 框架的 C 端域重设计);wish pool 联动主动回访;对账数据(十题答案)作为第一批校准样本。
- Exit:回访用户(带记忆)的规划时长/质量相对首访可度量提升。

### Stage 4:B2B 包裹(两层为什么的实证)
- Entry:Stage 3 exit + P6 推演结论确认。
- 做什么:principal/sponsor 分离的插件化——换入口与库存池、包裹 sponsor 配置,内核零改动跑通一个 B2B 场景(旅行社嵌入)。
- Exit:「99% 复用」从架构论断变为实测数字。

## 5. ADR(架构决策记录)

| # | 决策 | 备选与取舍 | 淘汰/复审条件 |
|---|---|---|---|
| ADR-1 | Z3 作可行性判定层 | 规则引擎(表达力不足)/OR-Tools(优化强、归因弱)/纯 LLM(4.4% 可行率) | 单次求解 >500ms 或变量规模 >10³ 时评估 OR-Tools;unsat core 是不可让渡特性 |
| ADR-2 | 双实现:TS 生产 + Python oracle | 单实现(无对账)/TS-only(失 oracle)| 差分测试连续 20 次无分歧后,Python 降为金标准用例库 |
| ADR-3 | 桥接面收敛:进程内优先,CLI/JSON 为边界 | 全 TS(失 oracle)/全 Python(失 dsh 生态)| 每桥 ≤2 个;延迟 >500ms/次才考虑常驻进程 |
| ADR-4 | loopx 为长程控制平面 | 自研状态机(重造轮子)| loopx 概念与需求冲突且无法适配时 |
| ADR-5 | 统一行程模型(§3) | 维持双引擎(债滚动)| 迁移完成日 = engine.* 退役日 |
| ADR-6 | 静态数据包(demo 期) | 直接接 API(供应链未选型,阻塞 demo)| Stage 2 进入时整体退役为测试夹具 |
| ADR-7 | 算术/求解分层 | 混合(不可测)| 永不复审 |
