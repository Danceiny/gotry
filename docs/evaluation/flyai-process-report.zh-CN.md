# FlyAI 进程结果测试报告

> 定位：验证 CLI 终止诊断及其对注册检索工具和库存事实的影响。
> 状态：实现验证中，最终提交完整回归待完成。
> 上游：[架构](../architecture.zh-CN.md)、[效应策略](../design/effect-interpreter.zh-CN.md)、[#514](https://github.com/Danceiny/gotry/issues/514)。
> 下游：能力层维护者与 PR 审查者。

## 问题与证据边界

一次 Node 22.23.2 完整回归在混合酒店夹具失败：预期的畸形比例 `1/2` 变成了 `exit -1`。完整执行耗时 1078.59 秒，退出码为 1；日志 SHA-256 为 `ef84759ec88a6eeedcdc60ea32cc87a2121aaa5bf1127e65185a43035cef604b`。helper 丢弃退出信号，且未保留 5000 ms 时限是否触发，原日志不足以确定失败原因。

临时诊断副本证明，外部 SIGTERM 与时限触发后的 SIGKILL 均被记为 `exit -1`。混合酒店数据返回预期比例，显式空输出对照返回解析错误。临时驱动为空输出复用了酒店标签，已独立核对实际输入。这些是诊断对照，没有复现原始偶发原因。后续宿主压力和一次通过的基线 FlyAI 测试需要保留，但不能证明根因已经修复。

报告覆盖注册工具 `gotry_flyai_search`、生产效应解译器、真实隔离 CLI 子进程、结果序列化及库存事实侧车，仅以本地受控可执行文件替换 CLI。这是本地适配器和策略的端到端验证，不包含真实 FlyAI 网络、模型、账号、预订或支付验收。

## 契约与实现

每次尝试调用 CLI 都携带有限的 `process` 记录：可为空的 `exitCode` 与 `signal`、布尔值 `timedOut`、单调时钟耗时 `elapsedMs`，以及可选的系统 `spawnErrorCode`。参数拒绝不产生进程记录。成功、空结果、畸形数据和失败均保留该诊断。新增终止诊断不带启动原文、路径、参数、环境值或部分输出。

`timedOut` 表示在观察到退出前，配置时限已经触发，不证明观察到的信号由谁发送。退出时停止定时器，标准流关闭延迟不算仍存活子进程的超时；耗时包含启动至流关闭和输出回收。保留原有 stdout 临时文件方案，避免管道截断。

启动失败、信号终止、时限触发或未知的空退出码时，先返回 `error`，再考虑其他分支，避免把部分输出中的 429 当成额度耗尽。普通非零退出仍保留既有的额度分类。效应解译器依据进程记录禁止这些本地终止结果自动重试，上游瞬时错误策略保持不变。错误结果不得产生正、负库存事实。

## 验证矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 参数拒绝 | 不调用效应，不启动 CLI，不产生进程记录或库存事实。 |
| stderr 延迟关闭 | 主进程正常退出保持非超时，受控后代最终释放标准流，保留进程诊断。 |
| 普通上游 HTTP 500 | 实际启动 CLI 两次，随后 miss 并产生一条负事实，保留既有重试。 |
| 正常退出 23 | 精确退出码，没有信号或超时，只尝试一次，不落库存事实。 |
| SIGTERM 且带 429 文本 | 仍为进程信号错误，不归配置问题，不自动重试。 |
| 受控时限 | 分别记录时限触发与观察到的 SIGKILL，只尝试一次，不落事实。 |
| 可执行文件不存在 | 安全的 ENOENT 码，不泄露命令、路径或参数，不重试、不落事实。 |
| 空 stdout | 进程正常退出后报告解析错误，不误判成无库存。 |
| 混合酒店数据 | 保留畸形 `1/2` 错误，不落事实。 |
| 普通 exit 1 加 429 | 保留 needs-setup 行为，不落库存事实。 |
| 合法 miss 与 hit | 保留进程诊断，并记录相应的精确日期事实。 |

## 复现与剩余限制

```sh
(cd ts && npx tsc --noEmit)
(cd ts && npx tsx scripts/flyai-process-proof.ts)
(cd ts && npx tsx scripts/flyai-tests.ts)
node scripts/build-dist-compat-tests.mjs
GOTRY_SESSION_LIVE=0 GOTRY_HBCLI_LIVE=0 GOTRY_HOTELBYTE_SKILLS_LIVE=0 GOTRY_LAVISH_LIVE=0 bash scripts/run-all-tests.sh
```

在 PATH 中选择目标 Node，并使用临时 HOME。FlyAI 测试调用进程验证，因此既有完整回归入口也会覆盖。没有延长时限、增加自动重试，或放宽畸形数据及事实断言。本次验证覆盖受控的直接 CLI，不证明继承标准流的任意后代均能被清理。原始未记录诊断的失败原因仍未明确，后续单次变绿不能关闭这一问题。独立有界对照还确认：后代持有 stderr 时，旧实现和修复版本在 500 ms 时限配置下，2000 ms 后仍未返回；终止测试拥有的后代才释放结果。这一既有的流回收边界缺陷由 [#516](https://github.com/Danceiny/gotry/issues/516) 独立跟进。
