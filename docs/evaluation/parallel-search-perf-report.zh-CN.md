# 搜索并行性能测试报告

> 角色：issue #519 的实测证据与剩余验收缺口。
> 状态：持续维护——受控真实安装入口目标已通过，全量回归与审查待完成（2026-09-20）。
> 上游：[架构](../architecture.zh-CN.md)；[issue #519](https://github.com/Danceiny/gotry/issues/519)。
> 下游：实现审查人与功能验收负责人。

## 结论与范围

预先固定的三组配对测试，将整轮中位耗时从 **8316 毫秒降至 3077 毫秒，降低 63.0%**，达到固定四查询工作负载的 50% 目标。每轮保留四条有序结果并正常退出。部分失败、依赖查询和用户取消，也已通过真实安装产品验证。

GoTry 安装包、dsh 宿主、注册工具、供应商子进程与终端退出均为真实链路。模型使用本地 SSE 脚本，供应商使用本地 CLI 夹具；HOME、DSH_HOME、工作目录和临时文件均隔离，不使用真实供应商、凭据或创始人数据。这证明预定计划的执行行为，不能证明自主规划质量，也不能外推线上行程普遍提速 63%。

## 行为端到端验证

[行为测试脚本](../../scripts/parallel-search-behavior-e2e.mjs)的前两个正确性场景使用 300 毫秒供应商延迟，不计入性能样本。

| 场景 | 校验内容 | 结果 |
|---|---|---|
| 四条独立查询，一个来源失败 | 并发峰值为 4；成功酒店保留 ID、名称与价格；两条合法空结果仍为 miss；失败目录保留 unavailable 和原始错误；结果顺序不变 | 通过；正常退出，3004 毫秒 |
| 先查目录，再查依赖目录结果的酒店 | 使用实际目录结果中的城市名；前一步供应商结束后才开始；两条结果保留，并发为 1 | 通过；正常退出，2262 毫秒 |
| 用户取消四条在途查询 | 四个供应商均就绪后，仅向安装产品发送 SIGINT；测试兜底清理之前，确认四个供应商与四个后代 PID 均已退出 | 通过；取消后 542 毫秒退出 |

纯提交代码还通过了 hbcli、Anything、进程取消、效应解译器四套回归与类型检查。进程用例覆盖预取消零派发、脱离进程组但持有管道的后代、回收不完整错误，以及先取消后到超时边界。这些局部验证用于支撑端到端证据，不能替代端到端结论；不宣称未知的组外后代已全部回收。

## 保留的失败与限制

早期诊断候选来自未提交快照，首次整体中位耗时为 8356 毫秒，对照历史基线 7980 毫秒，没有达到目标。后续配对测试遇到 809 秒温度保护休眠；中断的第三次基线与未执行的末次候选保留，不能算出通过的配对中位数。

最终提交候选的首次行为测试返回了预期查询输出，但没有在超时前退出。电源日志显示，测试期间发生了 900 秒维护休眠（UTC+04:00 的 05:09:32–05:24:32），整轮墙钟耗时 910299 毫秒。失败回执完整保留；后续运行才加入上述仅限测试进程生命周期的防休眠措施，两次中断均未改记为通过。

## 复现与剩余工作

使用分别安装的 tarball、相同依赖与全新的输出目录。脚本保留模型请求、供应商事件、标准输出、错误输出和断言。

```sh
caffeinate -s node scripts/parallel-search-perf-e2e.mjs /absolute/baseline/node_modules/.bin/gotry /new/baseline-output serial - 1
caffeinate -s node scripts/parallel-search-perf-e2e.mjs /absolute/candidate/node_modules/.bin/gotry /new/candidate-output parallel - 1
caffeinate -s node scripts/parallel-search-behavior-e2e.mjs /absolute/candidate/node_modules/.bin/gotry /new/behavior-output
```

按预定顺序将前两条命令交替执行三组，再比较中位数。不反复重试凑分，也不扣除启动耗时。关单前仍需全量回归、独立审查与合并读回；取消缺陷由 [#522](https://github.com/Danceiny/gotry/issues/522) 跟踪。不宣称已发布或已通过线上供应商验收。
