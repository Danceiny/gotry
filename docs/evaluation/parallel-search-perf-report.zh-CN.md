# 搜索并行性能测试报告

> 定位：记录 issue #519 的实测证据与剩余验收缺口。
> 状态：持续更新；性能目标尚未证实（2026-09-20）。
> 上游：[架构](../architecture.zh-CN.md)；[issue #519](https://github.com/Danceiny/gotry/issues/519)。
> 下游：实现审查者与功能验收负责人。

## 证据边界

测试真实安装的 GoTry 包、dsh 宿主、注册工具、供应商子进程和终端退出。模型由本地 SSE 服务回放，供应商由本地 CLI 夹具返回合法空结果。HOME、DSH_HOME、工作目录和临时文件全部隔离，没有使用真实供应商、凭据或创始人的产品数据。

本次证明预定计划的执行行为，不能证明自主任务拆分、线上供应商速度、有内容结果的质量或功能完整验收。候选版本包含 `ce6a92abaf6e32c1b1501a54bde558284330c970` 之上已记录哈希、尚未提交的 Traex 改动，属于诊断快照，不代表最终提交验收。

## 方法与版本

- Node 为 `v24.10.0`；GoTry 包版本为 `0.0.1-rc.24`；dsh、dsh-tools、dsh-agent-loop 均为 `0.1.5-rc.1`。两个安装目录的三份宿主包清单 SHA-256 一致。
- 历史基线提交为 `7f5f86893899fdf083bf1b261bf54e07cebf16f8`，树为 `8ad8593974d7cc64a0acd49ea3677b7e9afeab9b`。
- 两个版本在同一模型轮次收到相同的四条查询：杭州、南京各自的酒店与目的地目录查询，入住日期为 2027-01-15 至 2027-01-17。测试前固定每条供应商调用延迟为 1500 毫秒。
- 主要指标为进程启动到正常终端退出的耗时，包含启动成本。验收要求中位数至少下降 50%，且保留四条结果顺序与来源标记。供应商阶段耗时仅为辅助指标。
- 首轮两个版本各测三次。后续配对顺序预先固定为基线、候选交替三次；未跑完的序列不能给出验收中位数。
- 候选压缩包 SHA-256 为 `6b88f27372815edd82183a0d4dc78ec47bb2edcddb4f19685902731db525e801`。
- 候选注册工具源码 SHA-256 为 `999310600e5c5e7f960460f6d349daf1dd8f186d74a8dae5af9ae5f229389793`；进程辅助模块为 `655853ea05683c703e9908d183b0d543b3c20f2efc84ec2fadbdd6a3b5daa4dd`。

## 结果

| 测试组 | 总耗时，毫秒 | 供应商阶段，毫秒 | 供应商并发峰值 | 结果 |
|---|---|---|---|---|
| 历史基线，三次 | 8569 / 7980 / 7778 | 6132 / 6116 / 6128 | 1 / 1 / 1 | 四条结果，均正常退出 |
| 首轮候选，三次 | 21735 / 7027 / 8356 | 1515 / 1523 / 1537 | 4 / 4 / 4 | 四条结果，均正常退出 |
| 配对基线一／候选一 | 8625 / 8087 | 6093 / 1512 | 1 / 4 | 归一化时间戳后，结果内容和顺序完全相同 |
| 配对基线二／候选二 | 12682 / 7945 | 6425 / 1504 | 1 / 4 | 归一化时间戳后，结果内容和顺序完全相同 |
| 配对基线三 | 817233，超时 | 未完成 | 观测到 1 | 环境中断，最后一条候选样本未执行 |

首轮候选中位数为 8356 毫秒，历史基线为 7980 毫秒，**没有达到整体耗时下降 50% 的目标**。并发已经发生，但供应商阶段变快不能代替 issue 的完整目标。历史和当前样本采集时间不同，因此也不能据此认定产品改动导致变慢。

电源日志记录，第三次配对基线期间，机器于 UTC+04:00 的 03:25:50 因温度保护休眠了 809 秒。该轮工具结果包含来源不可用和轮次超时。失败记录保留，不计算「通过」的配对中位数；后续负载测试等待主机稳定再执行。

## 行为端到端验证

同一份冻结的实际安装候选包也通过了[行为测试脚本](../../scripts/parallel-search-behavior-e2e.mjs)，每条供应商调用延迟为 300 毫秒。这些是正确性场景，不是新增的性能样本。

| 场景 | 校验内容 | 结果 |
|---|---|---|
| 四条独立查询，一个来源失败 | 并发峰值为 4；成功酒店保留 ID、名称和价格；两条合法空结果仍为 miss；失败目录保留 unavailable 和原始来源错误；结果顺序不变 | 通过；正常退出，3152 毫秒 |
| 先查目录，再查依赖目录结果的酒店 | 酒店查询使用实际目录结果中的城市名；前一步供应商结束后才开始；两条结果保留，并发为 1 | 通过；正常退出，2389 毫秒 |

两例均使用隔离状态和真实安装宿主，不能证明模型能自主生成计划、取消后的回收或最终提交验收。原始模型请求、供应商事件、输出与断言保留在本地回执中。最终代码提交后仍需复测这两个场景。

## 复现与剩余工作

使用[真实安装入口测试脚本](../../scripts/parallel-search-perf-e2e.mjs)，针对依赖相同、分别安装的基线包与候选包执行，每次指定全新的输出目录。脚本保留回执、供应商事件、模型请求、标准输出和错误输出，校验四条结果的内容、顺序与来源，并记录墙钟与单调时钟耗时。

```sh
node scripts/parallel-search-perf-e2e.mjs /absolute/baseline/node_modules/.bin/gotry /new/baseline-output serial
node scripts/parallel-search-perf-e2e.mjs /absolute/candidate/node_modules/.bin/gotry /new/candidate-output parallel 7980
```

不能反复测试直到分数理想，也不能从主要指标中减掉启动时间。先冻结最终提交，在稳定主机上定位启动开销，再按预先固定的配对顺序执行并保留所有结果。功能验收还需要依赖查询、部分失败、取消与进程回收、有内容结果质量、全量回归，以及审查和合并证据。Issue #519 保持打开。
